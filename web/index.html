Connect & install

Start in BOOTSEL mode

  1. Disconnect the board from any external target.
  2. Hold BOOTSEL while plugging the Pico into USB.
  3. Release BOOTSEL. Choose the RP2040 bootloader below.

Pico W and Pico 2 are not supported. USB identification cannot distinguish every RP2040 board: check your board model.

Start in WCH ISP mode

  1. Disconnect any external target. Set BOOT0 high, BOOT1 low, then reset/power-cycle.
  2. Connect the ISP-capable USB port (USBHS on the reference board), not WCH-Link.
  3. After connecting below, restore BOOT0 low without resetting, so installation can reboot into the firmware.

Check your board's schematic and jumpers. Protected chips and incompatible memory partitions are rejected; option bytes are never changed.

USB access & udev rules

Linux: browser device selection does not grant OS access. The Pico bootloader is 2e8a:0003; permissions for the running DediBridge device (0483:dada) do not cover BOOTSEL mode. WCH ISP also has separate bootloader IDs.

Download 70-dedibridge.rules. These rules grant access to the active desktop user, not everyone:

On other systemd Linux distributions, install the downloaded file: 

sudo install -m 644 70-dedibridge.rules /etc/udev/rules.d/70-dedibridge.rules
sudo udevadm control --reload-rules

NixOS: put the downloaded rules beside your Nix module, add the following, then run sudo nixos-rebuild switch. Do not edit the generated /etc/udev files directly. Installing the file as 70-* ensures its tags are set before logind's 73-seat-late.rules applies access ACLs. 

services.udev.packages = [
  (pkgs.writeTextDir "etc/udev/rules.d/70-dedibridge.rules"
    (builtins.readFile ./70-dedibridge.rules))
];

After applying the rules, unplug the board and replug it in BOOTSEL/ISP mode, then click Connect bootloader again. Use a local desktop session; headless users need an explicit device-access group. Do not run your browser as root.

Windows: use a WinUSB driver on the bootloader's vendor interface, not the Pico's mass-storage interface. Browser or enterprise USB policies can also block access. udev rules only apply to Linux.
